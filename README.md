# 赤鲤 · 专业匹配 / 志愿预测 / 方案生成 / 专业先导课

> AI 高考志愿辅助 \& 大一趣味成长平台 —— \*\*功能 01：AI 专业智能匹配推荐\*\*、\*\*功能 02：院校录取概率预测\*\*、\*\*功能 03：冲稳保志愿方案生成\*\*、\*\*功能 04：专业 MOOC 先导课推荐\*\*

先做一套 18 / 34 / 48 题的五级量表问卷（MBTI 那种「完全不认同 → 非常认同」），用规则引擎在 21 个专业里排出匹配度；
再输入分数或位次，用「位次法 + 线差法」双模型叠加近三年录取波动，算出每个招生单位（专业组或具体专业）的录取概率，
并自动划分为 **冲 / 稳 / 保** 三档；然后把结果排成一张可以直接照着填的志愿表（支持打印 / 导出 PDF），
最后按专业推荐几门能先试听的大学先导课。前端主色为**正红 `#E60012`**，红金配色。

* 后端：Python 3.10+，**只用标准库**（无 FastAPI、无第三方依赖）
* 前端：原生 ES Module + CSS，**免构建**，由同一个 Python 进程托管
* 数据：两套可切换 —— 默认 **mock**（固定种子模拟：21 个专业 / 45 所院校 / 810 个专业组 / 3 年）；
`--data real` 切到 **八个地区的真实投档线**（104,115 个招生单位 / 122,995 条年度投档记录 / 2024–2026）
  * 院校专业组模式：江苏、广东（2024–2026）、山西（2025–2026）、湖北（仅 2026），分物理类 / 历史类
  * 「专业+学校」模式：**辽宁、浙江、山东、河北**，投档单位就是具体专业，浙江另带官方招生计划数
  * 全部来自各省教育考试院公开发布的文件；只收录投档分数齐全的省份，缺数据的不占位
* 匹配打分：**纯规则引擎，不联网、不调模型**，全部在本机算完

## 快速开始

```bash
cd gaokao-platform
python run.py                # 模拟数据（演示用）
python run.py --data real    # 八地区真实数据（江苏 / 广东 / 湖北 / 山西 / 辽宁 / 浙江 / 山东 / 河北）
```

浏览器会打开 [http://127.0.0.1:8000/](http://127.0.0.1:8000/)；加 `--no-open` 可关闭自动打开，`--port 8080` 可换端口
（端口被占用时会自动顺延）。

第一次打开会跳到登录页，用**邮箱 + 密码**注册一个本地账号即可（不校验邮箱真实性、不发邮件）。
账号只存在这台电脑的 `backend/data/app.db`，换台机器要重新注册。

### 两套数据源的区别

||`mock`（默认）|`real`|
|-|-|-|
|覆盖|江苏 / 广东 × 物理类 / 历史类|八地区：江苏、广东、山西、湖北（院校专业组）+ 辽宁、浙江、山东、河北（专业+学校）|
|招生单位|45 所 / 810 个|104,115 个 / 122,995 条年度记录|
|年份|2023–2025（3 年趋势）|2024–2026（3 年，主用 2026）|
|算法|三年位次加权 + 斜率外推 + 双模型融合|**位次等值法**：2026 实际位次 → 2027 概率|
|说明|演示数据，分数与位次均为生成|来自各省教育考试院公开的投档线与一分一段表|

`real` 模式的数据按省分目录放在 `backend/data/{js|gd|hb|sx|ln|zj|sd|he|cq}/`，文件名统一为
`toudang_{年份}_{physics|history|zonghe}.csv` 与 `curve_{...}.csv`，列是
`code,college,unit_code,unit_name,requirement,score,plan,rank`（专业组模式 `unit_code` 是组号、
`unit_name` 留空，专业模式 `unit_name` 是专业名）。要加省份，在 `real_data.py` 的
`PROVINCES` 里加一条配置（省份、`unit` 是 `group` 还是 `major`、科类、各年本科线）即可，
新增省份要保证当年投档线与一分一段表齐全、科类齐全；缺数据的省份不占位，宁可少一个省，也不在页面上露半张表。

> 无需 `pip install` 任何东西。Windows 下也可以直接双击 `start.bat`。

### 给没有 Python 的电脑用：打包成 exe

```bash
python build_exe.py
```

产物在 `dist/`：`chili.exe`（约 12 MB，单文件）与 `使用说明.txt`。把这两个拷到任何一台 Windows
机器上双击即可，**目标机器不需要装 Python、不需要联网**，前端与八个省份的投档数据都打在 exe 里。

- 账号库 `data/app.db` 会生成在 **exe 同级目录**，换机器时连同 `data/` 一起拷走，账号就跟着走；
- 第一次启动要等 3–5 秒（onefile 在解压数据），之后秒开；
- 关掉命令行窗口就等于停掉服务；
- PyInstaller 单文件包偶尔被杀毒软件误报，选「允许运行」即可。

想改数据或改代码后重新出包，再跑一次 `python build_exe.py`（会自动清掉 `build/` 中间产物、
覆盖 `dist/chili.exe`）。

## 账号与登录

四个页面和所有数据接口都需要先登录（`/login.html` 之外全部拦截），登录状态靠一个
`HttpOnly; SameSite=Lax` 的 Cookie 维持，默认 7 天有效，用了一半时间会自动续期。

|项目|做法|
|-|-|
|存储|SQLite，`backend/data/app.db`，两张表 `users` / `sessions`|
|密码|PBKDF2-HMAC-SHA256，60 万轮，随机 16 字节盐，`hmac.compare\_digest` 比对|
|会话|库中只存 token 的 SHA-256，浏览器拿明文；退出立即失效|
|限流|同一邮箱连错 5 次锁 10 分钟；同一 IP 10 分钟 20 次；同一 IP 每小时最多注册 5 个号|
|防枚举|邮箱不存在和密码错误返回同一句话，只有剩余次数不同|
|CSRF|写接口校验 `Origin`，跨站直接 403；Cookie 带 `SameSite=Lax`|
|响应头|`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: same-origin`|

忘记密码（没有邮箱找回，直接在本机重置）：

```bash
cd backend
python -m app.auth reset 你的邮箱      # 交互式输入新密码
python -m app.auth list                # 看有哪些账号
python -m app.auth delete 你的邮箱     # 删号
```

**换成 MySQL**：所有 SQL 都集中在 `auth.py` 的 `AuthStore` 里，列类型已经按两边通用的写法
（`INTEGER PRIMARY KEY`、`VARCHAR(n)`、整数时间戳、布尔存 0/1、邮箱统一小写入库）。
上线时照 `AuthStore` 的方法签名写一个 `MySQLUserStore`（约 200 行），把 `serve()` 里的一处构造换掉即可，
业务层不用动；限流那份内存字典换 Redis。

## 匹配模型（功能 01）

三套问卷共用同一套打分，区别只在题量与覆盖维度。题目是 MBTI 那种陈述句 + 五级量表：
「完全不认同 / 不太认同 / 说不好 / 比较认同 / 非常认同」（内部记为 1–5）。

|规格|题量|覆盖|适合|
|-|-|-|-|
|快测 quick|18|兴趣|完全没方向，先看个大概|
|标准 standard|34|兴趣 + 学科能力 + 工作偏好|大多数人|
|深度 deep|48|再加性格倾向与硬条件（学制 / 实验 / 地域）|想更贴自己|

`得分 = 0.72 × 兴趣 + 0.18 × 学科能力 + 0.10 × 工作偏好`，再减去硬条件惩罚：

1. **兴趣**：每题在六个维度（数理逻辑 / 工程动手 / 生命健康 / 商业嗅觉 / 人文表达 / 社会服务）上带权重，
答 `level` 折算成 `delta = (level − 3) / 2`（−1 … +1）后累加；18 道兴趣题里每个维度是 2 道正向 + 1 道反向，
反向题取负号。累加后与专业画像的维度向量做余弦相似度；`ratio = clamp((cos − 0.35) / 0.65, 0, 1)` 再取 `1.6` 次幂拉开差距
（实测跨度 0.04–1.00）；
2. **学科能力**：a01–a06 自评（数学 / 物理化学 / 语文写作 / 英语）按 `(level − 1) / 4` 折算，对应专业的 `gate` 要求；
3. **工作偏好**：p01–p10 每题带一个标签（高薪 / 稳定 / 科研 / 创造 / 自由 / 工程 / 人文 / 长学制），
取该标签的最大强度，按加权命中率计分；
4. **硬条件惩罚**：长学制（临床医学、口腔医学）`−0.26`、偏实验方向 `−0.14`、跨地域 `−0.05`（同城 `+0.05`）；
问卷里只有「比较认同 / 非常认同」才算数，避免中性答案被当成承诺；
5. **高分压缩**：`score > 0.88` 时 `0.88 + (score − 0.88) × 0.72`，避免一屏多个 99/100；
6. **答得太模糊会提示**：全是「说不好」或多个维度的平均强度接近峰值时，结果里会多一句「你的兴趣分布比较平均……都可以试试」；
兴趣全是中性（一个正向峰值都没有）直接拒绝，请至少几道题给出「比较认同」；
7. **结果**：前 6 个专业，每个带一句「为什么是它」、两三条命中标签、3 所开设院校，以及置信度（按题目覆盖度给出）。

问卷答案只存在浏览器里，点「开始匹配」才发一次 POST，服务端不落盘、不记录。

## 预测模型

对每个招生单位取 2023–2025 三年的最低录取位次：

1. **加权基线**：近三年权重 `0.2 / 0.3 / 0.5`，越近越重要；
2. **趋势外推**：用首尾两年的斜率外推一年，并把斜率限制在基线的 ±15% 以内，避免异常抖动；
3. **位次概率**：`z = (预测最低位次 − 你的位次) / scale`，`scale` 取「三年波动 × 2」「预测位次的 30%」「800」三者最大值；
用 logistic 函数把 z 映射到 0–1；
4. **线差概率**：把预测位次反查一分一段表得到预测最低分，用分数差再做一次 logistic；
5. **融合**：`概率 = 0.75 × 位次概率 + 0.25 × 线差概率`，裁剪到 1%–99%；
6. **分档**：`≥85%` 保、`45%–85%` 稳、`<45%` 冲；
7. **可信度**：由三年位次的变异系数给出（高 / 中 / 低 + 0–100 分）。

分数与位次只填一个时，用内置的模拟「一分一段表」（对数线性插值的累计占比曲线）互相换算；
两个都填时各用各的，不做强行校准。

## API

|方法|路径|说明|
|-|-|-|
|GET|`/api/health`|健康检查|
|GET|`/api/meta`|省份 / 科类 / 年份 / 院校数 / 招生单位数 / 每省的 `unit`（group 或 major）|
|GET|`/api/quiz`|三套问卷的规格列表（题量、覆盖维度、预计用时）|
|GET|`/api/quiz/{quick\|standard\|deep}`|某套问卷的完整题目|
|POST|`/api/match`|专业匹配，body：`{spec, answers, limit?}`，`answers` 形如 `{"i01":4,"a02":3,...}`（1–5）|
|POST|`/api/predict`|预测，body：`{province, track, score?, rank?, tier?, limit?, college?}`；带 `college` 时只算这一所，按往年分从高到低全量返回|
|GET|`/api/colleges?q=南京&province=\&track=`|按校名搜索（完全相等 > 前缀 > 包含 > 城市，名字短的优先），不带 `q` 时返回该省该科类全部院校|
|GET|`/api/college/{id}?province=\&track=`|单所院校在该省该科类的所有招生单位（专业组或专业）及录取数据|
|POST|`/api/plan`|生成冲稳保方案，body：`{province, track, score?, rank?, chong?, wen?, bao?, mode?}`，`mode` 取 `auto\|school\|major`|
|GET|`/api/curve?province=\&track=\&score=`|一分一段：分数 → 位次（三年并列）|
|GET|`/api/curve?province=\&track=\&rank=`|一分一段：位次 → 分数|
|GET|`/api/mooc?major=\&limit=`|按专业推荐先导课|
|GET|`/api/mooc/majors`|课程库覆盖的专业目录|
|POST|`/api/auth/register`|注册，body：`{email, password}`，成功后直接建会话（201 + Set-Cookie）|
|POST|`/api/auth/login`|登录，body：`{email, password}`|
|POST|`/api/auth/logout`|退出，清 Cookie|
|GET|`/api/auth/me`|当前登录的账号；未登录 401|

**`login.html` · 登录 / 注册**

* 同一个卡片里切换登录和注册，注册成功自动登录并回到 `next=` 指的页面；
* 防呆：邮箱自动去空格转小写、失焦才报错、密码三条规则实时打勾、两次密码实时比对、
CapsLock 提示、密码可切换明文、`autocomplete` 填对、移动端字号 16px 防缩放；
* 提交期间按钮转圈并禁用，防止重复提交；邮箱已注册时提示并一键切到登录、邮箱自动回填；
* 账号被锁定时会直接说「还能再试 N 次」/ 锁到几点；忘记密码引导到 `help.html#reset`（本站不发邮件，由人工核验后重置）；

**`quiz.html` · 功能 01 专业匹配**

* 三阶段：选规格（18 / 34 / 48 题三张卡片）→ 逐题作答 → 结果；
* 每题一句陈述 + 五档量表（完全不认同 → 非常认同），点数字或按 `1`–`5` 作答，选中 240ms 后自动翻页；
* 键盘还支持 `←` `→` 换题；没把握可以「下一题」跳过，结果里会按实际作答数算置信度；
* 结果：兴趣维度条形图（0–100）、6 个专业按匹配度排序、命中标签、3 所院校、先导课入口；
* 深链：`/quiz.html?spec=standard`。

**`predict.html` · 功能 02 录取概率预测**

* 输入：省份、科类、分数、位次（选填），支持示例一键填充；
* **查找学校**：表单下方直接输校名（如「南京大学」「东南」），下拉里选一所就只看这所学校——按 2026 年最低分从高到低列出
  它的每个专业/专业组及录取概率，排序控件自动置灰；点「清除」或换省份/科类恢复完整结果。匹配规则是
  「完全相等 > 前缀 > 包含 > 城市」，同样命中时名字短的优先（搜「东南」先给东南大学，不会先给东南大学成贤学院）；
* 结果：冲稳保统计、档位筛选、四种排序（默认**匹配度优先**，即与你位次最接近的排前面）、分页加载；
* 详情：点卡片打开右侧抽屉，含历年录取表、同校其他招生单位切换（专业模式下是可搜索的专业列表）、志愿建议与可信度；
* 结果区下方给出「下一步」两张卡片，带参数跳到方案生成 / 先导课；
* 深链：`/predict.html?province=江苏\&track=物理类\&score=620`，加 `\&open=1` 直接展开第一条详情，加 `\&school=<college_id>` 只看一所学校；
* 响应式：≤760px 单列，抽屉全屏。

**`curve.html` · 功能 05 一分一段查询**

* 输入分数查全省位次，或输入位次反查分数，两者填一个即可；
* 结果把 2026 / 2025 / 2024 三年的同一个分数并列出来，一眼看出「同样的分，今年更不值钱」；
* 表格另给超本科线多少分、当年本科线、考生人数；底部一句话解释为什么填志愿要看位次；
* 深链：`/curve.html?province=江苏\&track=物理类\&score=600`（或 `\&rank=35000`）。

**`plan.html` · 功能 03 冲稳保方案生成**

* 三档数量自由可调，上限跟着省份走（江苏 40 个专业组、辽宁 112 个专业、浙江 80、山东/河北 96、广东/湖北/山西 45），
  右侧实时显示「共 N 个 / 本省可填 M 个」，点「按 2:4:4 填满」一键把整张表撑满；三档加起来超过本省上限时，后端按比例压缩并提示；
* 每档按预测分数排序并连续编号，同一所院校出现几次由「排法」决定：
  - **智能排**（默认）：院校专业组最多 2 个、专业模式最多 3 个，兼顾覆盖面与被录取可能；
  - **按学校**：一所学校只占一个志愿，把整张表铺到尽可能多的学校上（江苏 40 条 → 40 所学校）；
  - **按专业**：允许同一所学校的多个专业同时进表（专业组 3 个 / 专业模式 6 个），适合盯着某几个方向填；
  切换后立即按新口径重排，结果行会显示「覆盖 N 所学校」与当前排法说明；
* 「复制文本」把整张表复制成纯文本（含排法与覆盖面一行），「打印 / 导出 PDF」走浏览器打印（独立的打印样式：页头带排法、隐藏导航与表单、
压缩行距、A4 竖版，18 条志愿约 4 页）；
* 深链：`/plan.html?province=江苏\&track=物理类\&score=620\&chong=4\&wen=8\&bao=6`，加 `&mode=school|major` 直接指定排法。

**`mooc.html` · 功能 04 专业 MOOC 先导课**

* 输入专业名或用下方 8 个热门专业快选；结果按匹配度排序，给出平台、难度、周数、评分、学习人数、3 个标签和一句理由；
* 只推真正相关的课：课程库对不上就留空，用通识课补位并标成「通识补充」，不会把解剖学推给法学；
* 课程链接指向各平台的**搜索结果**，不伪造具体课程地址；
* 深链：`/mooc.html?major=计算机科学与技术`（首页抽屉底部也会带专业名跳过来）。

**内容页 · 关于 / 隐私 / 协议 / 帮助 / 404**

* `about.html`：数据来源表（2026 / 2025 投档线 + 逐分段表）、方法说明（位次等值法、σ 公式、分档阈值、为什么不用三年趋势）、回测表（中位误差 8.0 分、≤5 分 29.9%、≤10 分 60.2%）、分档命中率对照、已知局限、备案与主体信息；
* `privacy.html`：收集了什么、怎么用、不做什么（不卖不共享、无第三方统计、前端不加载外部脚本）、Cookie 说明、保存期限、用户权利、安全措施；
* `terms.html`：服务性质（辅助工具、非录取承诺、与高校无隶属）、账号规则、使用规范、知识产权、免责说明；
* `help.html`：四步上手、账号与登录、忘记密码、数据与准确度、常见问题、联系方式；
* `error.html`：404 页，给出返回入口，由服务端在找不到文件时返回（状态码仍是 404）。

站点结构：顶栏四个功能入口常驻，所有页面共用四栏页脚（产品 / 数据 / 关于 / 版权行），
页脚链接到上述内容页；顶栏右侧的「数据更新至 2026-07」也指向 `about.html#data`。

## 数据声明

`mock\_data.py` 中的所有分数、位次、招生计划均由固定随机种子生成，**不是真实录取数据**，
仅用于功能演示，不构成任何志愿填报建议。院校名称为真实名称，但与其录取情况无关。

`--data real` 模式的数据来自八个省教育考试院公开发布的普通类本科批投档线与逐分段统计表（`backend/data/{js,gd,sx,hb,ln,sd,zj,he}/`）：江苏、广东 2024–2026，山西 2025–2026，辽宁 2024 与 2026，湖北、浙江、山东、河北 2026。**八省全部接入、无占位省份**。投档线原文不含招生计划数（页面显示为"—"）；2024 年片段与 2025 / 2026 年
图片版一分一段表均经过 OCR 与累计人数校验，六张表的底端分数与官方本科线完全一致。
预测结果按位次等值法估算，误差约在 ±8 分 / ±9000 位次量级（见 `realdata/REPORT.md` 的江苏回测），
不构成录取承诺。
