## 三、数据层

### 3.1 全国选科模式（`backend/app/subjects.py`）✅

`PROVINCES` 是 **dict**（键为中文省名），31 个省级行政区，`mode` 三选一：

- `3+1+2`（23 省）：首选物理/历史，再选化学/生物/政治/地理 → **12 种组合**
- `3+3`（6 省市）：京、津、沪、鲁、琼 6 选 3 → **20 种组合**；**浙江 7 选 3（多一门技术）→ 35 种组合**
- `old`（西藏 / 新疆过渡期）：文理分科 → 2 种

每省带 `first`（首批年份）与 `batch`（第几批），前端显示「你所在省份哪一年开始新高考」。

**没有 `backend/data/subject_rules.json`**——92 个专业类的选科要求直接写在 `subjects.py` 的 `MAJOR_GROUPS`
（模块底部有 `assert len(MAJOR_GROUPS) == 92`，改数据时跑不起来就是漏了类）。

核心规则（2024 版「物化捆绑」）：

- 理学（除地理科学类、心理学类）、工学（除建筑类）、农学、医学（除护理学类）→ **物理 + 化学**必选
- 政治学类、马克思主义理论类、公安学类 → **思想政治**；历史学类 → **历史**
- 经济 / 管理 / 文学 / 教育 / 艺术 / 哲学多为**不限**；地理科学类、护理学类给 `any_of` 弹性

对外口径统一：页面必须写「以本省考试院当年公布的《选考科目要求》为准」。

### 3.2 专业 → 专业类映射（`backend/app/subject_map.py`）✅

821 个专业（含「（中外合作）」等后缀）映射到 92 个官方专业类，三级策略：
`EXACT` 精确表（约 300 条）→ `RULES` 关键词有序表 → `GROUP_HINTS` 旧 56 类兜底。

实测：`total=821, exempt=14, denominator=807, mapped=807, ratio=1.0, mapped_groups=90/92`。

- `is_exempt()` 把试验班 / 预科班排除在分母外（它们本来就不对应具体专业类）；
- `@lru_cache(maxsize=4096)` 把全量映射从 1.8s 压到 0.14s；
- 新增专业名映射不上时**不要改 `other`**——`stats()` 会报 `missed_total`，对着漏的名字补 `RULES` 关键词。

### 3.3 院校专业优势（`backend/app/major_colleges.py`）✅

**数据只有位次，没有学科评估。** 8 省投档数据的粒度不一样，这决定了一切：

| 省份 | 粒度 | 条数 |
| --- | --- | --- |
| 辽宁 / 浙江 / 山东 / 河北 | 专业级（`kind="major"`） | 81,420 |
| 江苏 / 广东 / 湖北 / 山西 | 专业组（`kind="group"`，如「09专业组」） | 22,695 |

专业组反推不出具体专业，所以接口给三态 `granularity`：

- `major`：用户省有专业级数据，直接用；
- `cross_province`：用户省只有专业组 → 回退到 4 个专业级省份，`note` 里说明「借它们的位次看梯队」；
- `nationwide`：不传省份，四省合并看。

两个实现要点：

1. **按校名聚合，不按 `college_id`**——同一学校每省各存一份 id（`he-physics-0284` / `ln-physics-0284`），按 id 聚合会把南京大学拆成两条。去重后 1725 → 870 所。
2. **`percentile` 用该条记录来源省的考生数**，不能用用户省的——跨省位次不可比。

排序按 `best_rank` 升序（跨年取最好位次）。实测查「计算机科学与技术」：870 所，Top 为中国科学院大学 177、复旦 258、南京大学 264、北航 326、武大 510，耗时 0.07s。

### 3.4 选科测评题库（`backend/app/choice_quiz.py`）✅

23 题，**不是 39 题**——高一学生耐心有限，一题一屏 6 分钟能答完比 8 分钟答一半强。

| 类型 | 题量 | 作用 |
| --- | --- | --- |
| 单选 | 16 | 学科偏好 / 能力自评 / 专业簇倾向 / 价值取向 |
| 五级量表 | 7 | 学科兴趣强度（1 完全不认同 … 5 非常认同） |

四维：`SUBJECT_KEYS`（物化生政史地技）、`ABILITY_KEYS`（逻辑/记忆/动手/表达/数据/空间）、
`CLUSTER_KEYS`（12 簇）、`VALUE_KEYS`（稳定/薪资/研究/兴趣）。

`public_questions()` 会剥掉 `scores` 只留题干和选项——**权重留在服务端**，改前端刷不出分。

### 3.5 推荐引擎（`backend/app/choice_engine.py`）✅

```
total = 0.45 × 学科契合 + 0.35 × 专业簇契合 + 0.20 × 覆盖率
覆盖率得分 = 100 × √(可报专业占比)      // 开根号，避免「多报一个专业」被过度奖励
簇契合 = 0.6 × 可达最强簇 + 0.4 × 前三簇均值   // 防止被大量 0 分专业稀释
```

- `_restrict_profile(profile, province)`：把该省选不了的科目清零。只有浙江能选「技术」，否则江苏学生看到「技术 85 分」会以为能选。
- 推荐专业每类最多 2 个，并过滤试验班 / 预科班。

**两个「说人话」的派生结论**（用户要求参考市面测评后补，见 m00761）：

```
tendency（文理倾向）  = 0.40·物理 + 0.25·化学 + 0.20·生物 + 0.15·技术   减去
                        0.45·历史 + 0.30·政治 + 0.25·地理
                        |diff|<8 文理均衡 / ≥18 明显 / 其余轻度
riasec（霍兰德六型）  = 12 个专业簇 → R/I/A/S/E/C 加权，再按最大值拉满 100
```

- `tendency` 存在的原因：3+1+2 的 23 个省份，学生第一个要拍板的就是「物理还是历史」，这个结论必须单独给，不能埋在三张组合卡里。
- `riasec` 拉满而不做跨簇平均：不归一化的话六型全挤在 20 分附近，用户看不出自己像什么。"I+R 研究型＋现实型" 是生涯规划行业通用语言，比自造术语好懂。
- 霍兰德映射表 `RIASEC_CLUSTERS` 是**手工定的**，不是问卷直接测出来的——问卷测的是学科兴趣和 12 个专业簇，六型是簇的投影。这条要在页面上说清楚，不能让人以为是标准霍兰德量表。

### 3.6 兴趣复测（`backend/app/mooc_retest.py`）✅

3 题固定 id：`invest`（愿意投入时间）/ `curiosity`（想继续了解）/ `resist`（遇到难课会退缩，反向计分）。
第二题题干会塞进该专业真实主干课名（取 `mooc_data._backbone`，失败回落空列表）。

`evaluate()` 给三态：`deep`（≥4，继续深入）/ `trial`（2–4，先试课）/ `switch`（<2，换专业）。

### 3.7 AI 层（`backend/app/ai_providers.py` + `ai_client.py`）✅

统一 OpenAI 兼容协议（`POST {base_url}/chat/completions`），纯 `urllib`，13 家：
`deepseek` / `qwen` / `doubao` / `kimi` / `zhipu` / `ernie` / `spark` / `hunyuan` / `minimax` / `stepfun` / `siliconflow` / `openrouter` / `local`。

- 口语别名：`moonshot`→`kimi`、`qianfan`→`ernie`、`ollama`→`local`；
- 智谱 / 文心 / 讯飞不支持 `response_format=json_object` 时自动去掉字段重试一次；
- `api_key` 可为空（Ollama 免 Key）；`AIError.code` 覆盖 13 种错误码，前端 `humanError()` 逐条翻译。

**密钥存储**：只存浏览器 `localStorage["chili.ai.config"]`，请求时放在 body 的 `ai` 对象里传给后端代理，
后端不落盘、不进日志。未配置时全部功能降级为规则引擎。

逐家申请教程在 `docs/AI接入指南.md`（含报错对照表）。

## 四、API 契约（全部 `{"ok":true,"data":...}` 包装；错误是 `{"ok":false,"error":"中文","code":"码"}`）

| 方法 | 路径 | 登录 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/choice/meta` | 否 | 省份 / 科目 / 92 类 / 题库统计 / `majors_total` |
| GET | `/api/choice/quiz` | 否 | 题目在 `data.items`，量表单独给 `data.scale` |
| GET | `/api/choice/combos?province=` | 否 | 该省全部合法组合 + 覆盖率 |
| POST | `/api/choice/report` | 否 | `{province, answers}` → 画像 + 3 组合 + 12 专业；顶层额外给 `tendency`（物理/历史倾向）与 `riasec`（霍兰德六型） |
| GET | `/api/major/colleges?name=&limit=&province=` | 否 | 优势院校（参数名是 **`name`**，不是 `major`） |
| POST | `/api/mooc/retest` | 否 | GET 出题，POST `{major, answers}` 判分 |
| GET | `/api/ai/providers` | 否 | 13 家厂商（已剔除 console / key_hint） |
| POST | `/api/ai/ping` | **是** | 测连通性 |
| POST | `/api/ai/chat` | **是** | 透传对话 |
| POST | `/api/ai/interview` | **是** | 选科追问（辅助，主路径是固定 23 题） |
| POST | `/api/ai/report` | **是** | 把规则结果讲成人话（分数仍以引擎为准） |
| POST | `/api/ai/coach` | **是** | **AI 主导的引导式对话**：`{history, profile, province, turn}` → `{say, ask, options, stage, done, suggestion}`；`stage` ∈ interest/ability/value/reality/close，最多 8 轮，`turn>=6` 强制收敛。JSON 解析失败退化为「一句回应 + 一个兜底问题」，不中断对话 |
| POST | `/api/ai/major` | **是** | **单专业顾问**：`{major, question, history, profile, combo}` → `{reply, level, points, probes}`；`level` ∈ match/caution/mismatch/unknown。服务端会把 `major_outlook` 的客观资料塞进 context，压住模型瞎编 |

AI 接口要求登录，是为了防止陌生人拿站点当免费 API 代理烧 Key。

> 为什么要 `/api/ai/major` 而不是继续扩 `/api/ai/report`：选科那道题答案基本唯一（92 个专业类的硬要求是公开规则），AI 在这儿只能润色；真正「没有标准答案」的是「这个专业到底学什么、我这种性格合不合适、和隔壁专业差在哪」，那才是模型该花 token 的地方。
