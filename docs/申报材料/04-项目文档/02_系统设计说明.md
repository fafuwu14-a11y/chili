# 系统设计说明

> 赤鲤 · 高一选科与专业规划平台｜2026 年 11 月

## 一、总体结构

```
                  浏览器（原生 ES Module，无构建）
   首页 / 向导 / 专业库 / 预测 / 培优扶弱 / AI 设置 / 登录弹窗
                              │  fetch JSON
                              ▼
        ┌─────────────────────────────────────────────┐
        │   server.py  stdlib http.server 路由层       │
        │   鉴权拦截 · CORS · 静态托管 · 错误码统一     │
        └───────┬──────────────┬──────────────┬───────┘
                │              │              │
        ┌───────▼──────┐ ┌─────▼──────┐ ┌─────▼────────┐
        │  规则与引擎层 │ │  数据访问层 │ │    AI 层     │
        │ subjects     │ │ real_data   │ │ ai_providers │
        │ subject_map  │ │ major_*     │ │ ai_client    │
        │ choice_quiz  │ │ mooc_data   │ │（可降级）     │
        │ choice_engine│ │ auth(SQLite)│ │              │
        │ major_colleges│ │            │ │              │
        └──────────────┘ └────────────┘ └──────────────┘
```

三层职责很清楚：**规则层算分，数据层出事实，AI 层只讲人话**。任何一层挂了，上层还能退。

## 二、核心模块

| 模块 | 行数量级 | 职责 | 关键设计 |
| --- | --- | --- | --- |
| `subjects.py` | ~600 | 31 省模式、7 门科目、92 个专业类的选科要求 | 专业类要求写成 `required` / `any_of` 声明式规则，`group_eligible()` 逐条判定；模块底部 `assert len(MAJOR_GROUPS) == 92` 防止漏类 |

| `choice_quiz.py` | ~300 | 23 题题库（16 单选 + 7 量表） | 7 学科 / 6 能力 / 12 专业簇 / 4 价值取向；`public_questions()` 剥掉分值，权重只留服务端 |
| `choice_engine.py` | ~700 | 组合评分、专业排序、RIASEC、文理倾向 | 见下一节 |

## 三、关键算法

### 3.1 组合评分

```
总分 = 0.45 × 学科契合 + 0.35 × 专业簇契合 + 0.20 × 覆盖率得分
覆盖率得分 = 100 × √(可报专业占比)
```

三个设计取舍：

1. **覆盖率开根号**。可报 90% 给 94.9 分、可报 30% 给 54.8 分——不开根号的话，覆盖率会直接吃掉兴趣分，等于又回到「选覆盖率最高的」。
2. **簇契合不取平均**。用 `0.6 × 最强簇 + 0.4 × 前三簇均值`。821 个专业里绝大多数与学生无关，直接平均会把每个组合都拉到 10 分附近，看不出差别。
3. **推荐专业时每类最多 2 个**。否则计算机类会一次占满 12 个名额，学生看不到「我还能报什么」。

### 3.2 RIASEC 与文理倾向

霍兰德六型由 12 个专业簇加权映射（如 tech → I 1.0 / R 0.55 / C 0.2）。得分后**按最大值拉满到 100**，不跨簇归一化——否则六型全挤在 20 分附近，学生看不懂。

文理倾向 = 物理侧（物理 0.40 / 化学 0.25 / 生物 0.20 / 技术 0.15）与历史侧（历史 0.45 / 政治 0.30 / 地理 0.25）的加权差：

- `|diff| < 8` 判「文理均衡」，`> 0` 偏理，`< 0` 偏文
- `|diff| ≥ 18` 标「明显」，否则「轻度」

3+1+2 省份的学生第一个决策就是物理还是历史，这个指数直接对应那一步。

### 3.3 院校优势

按校名聚合（同一学校在每省各存一份 `college_id`，按 id 聚合会把南京大学拆成两条），排序键是最佳录取位次（跨年取最好）。三个必须处理的现实：

| 现实 | 处理 |
| --- | --- |
| 只有 4 个省有专业级数据，另 4 省只有专业组 | `granularity` 三态：`major` / `cross_province`（回退并给说明）/ `nationwide` |
| 各省考生基数不同，位次不可直接比 | 百分位用**该条数据自己来源省**的考生数算 |
| 「计算机类」是专业类不是专业 | 模糊匹配时对以「类」结尾的候选降权 |

## 四、API 契约

统一响应：成功 `{"ok":true,"data":...}`，失败 `{"ok":false,"error":"中文文案","code":"机器码"}`。

| 方法 | 路径 | 登录 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/choice/meta` | 否 | 31 省 / 92 类 / 题库元信息 / 821 专业 |
| GET | `/api/choice/quiz` | 否 | 23 题（已剥分值） |
| GET | `/api/choice/combos?province=` | 否 | 该省全部组合 |
| POST | `/api/choice/report` | 否 | 答案 → 组合 + 专业 + 倾向 + 霍兰德 |
| GET | `/api/major/colleges?name=` | 否 | 院校优势（位次排序） |
| GET | `/api/mooc/retest?major=` | 否 | 二次检验出题 |
| POST | `/api/mooc/retest` | 否 | 判分 → deep / trial / switch |
| GET | `/api/ai/providers` | 否 | 13 家厂商（不含 Key 提示） |
| POST | `/api/ai/chat` | 是 | 通用对话 |
| POST | `/api/ai/interview` | 是 | AI 追问一个专业问题 |
| POST | `/api/ai/report` | 是 | 把规则结果讲成人话 |
| POST | `/api/ai/major` | 是 | **专业顾问**：问什么学、适合吗、和相近专业区别 |
| POST | `/api/ai/coach` | 是 | **引导式对话**：AI 提问、学生答，`stage` 走 interest→ability→value→reality→close，最多 8 轮，`turn>=6` 强制收敛；返回 `{say, ask, options, stage, done, suggestion}` |
| GET/POST | `/api/predict` `/api/plan` | 是 | 三档联动推荐与志愿表 |

内容类接口不设登录门槛（可分享、可收录），只有烧 Key 和个性化计算的接口才要登录。

## 六、降级与容错

| 故障 | 表现 | 降级 |
| --- | --- | --- |
| 没配 AI Key | 顾问抽屉 | 显示「还没接入 AI」+ 去设置入口，主流程不受影响 |
| AI 返回非 JSON | 解析失败 | 保留纯文本回答，`level` 记 unknown，不断对话 |
| 用户省只有专业组数据 | 院校抽屉 | 回退到 4 个专业级省份并标注来源 |
| 浏览器禁 sessionStorage | 测评中途刷新 | try/catch 兜底，答案丢失但页面不崩 |
| 专业没有匹配课程 | 先导课 | 退回通识课并说明「直接对口课程不多」 |

## 七、安全

- 密码 PBKDF2-HMAC-SHA256、60 万轮、每账号独立 salt
- 会话 Cookie `HttpOnly` + `SameSite=Lax`，7 天过期
- 登录、注册、AI 调用按 IP 限流
- 请求体上限 256 KB（AI 对话历史需要，常规接口远低于此）
- API Key 只存在用户浏览器的 `localStorage`，服务端即用即弃、不落库；日志里只出现 `sk-****abcd`
- 所有 SQL 走参数化查询，`test_auth.SQLInjectionTests` 覆盖
