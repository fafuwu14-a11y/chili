## 一、项目是什么

**赤鲤**：面向高考考生/家长的志愿辅助 Web 平台。纯 Python 3.10+ 标准库后端（无第三方 Web 框架），原生 ES Module 前端（无构建步骤），同一进程托管。可打包成 Windows 单文件 exe（PyInstaller，约 12MB，目标机免装 Python、免联网）。

当前有 **4 个功能 + 1 个门户页**：

| 编号 | 功能 | 页面 | 后端 |
|---|---|---|---|
| — | 门户 | `frontend/index.html` | 无（只填下拉、跳转） |
| 01 | 专业匹配测评 | `frontend/quiz.html` | `backend/app/quiz_data.py` + `matcher.py` |
| 02 | 录取概率预测 | `frontend/predict.html` | `predictor.py` + `real_data.py`/`mock_data.py` |
| 03 | 一分一段换算 | `frontend/curve.html` | 同上 |
| 04 | 冲稳保方案 | `frontend/plan.html` | `planner.py` |
| — | 专业先导课 | `frontend/mooc.html` | `mooc_data.py` |

**后端约定**：`server.py` 里手写路由，形如
```python
if path == "/api/predict":
    return self._json(predictor.predict(...))
```
没有框架，参数用 `parse_qs` 取。新接口照抄现有块即可。

## 六、已知问题

1. **投档表里混着职业本科/专科的专业名**（`软件工程技术`、`物联网应用技术`、`航空智能制造技术`…）。`major_direction.majors_in_group` 用「同根名折叠 + 招生单元 < 40 且以技术/工程结尾」挡掉了大部分，但 `major.html` 的完整列表仍是原样 821 条，没有做同样清洗。
2. **大类画像只有 21 条**（`quiz_data.MAJOR_PROFILES`），而目录里有 56 个专业类。没进画像的专业类只能靠「方向细分」在结果页侧面出现，不会被单独推荐。
3. `README.md` 的「下一步」还没把「专业集合功能」写进去；`docs/DESIGN-home-match-v2.md` 是设计稿，实现与它还有距离。
4. **投档表的年份和专业维度都不齐**：只有辽宁能按专业做跨年对比（2024+2026，缺 2025）；浙江/山东/河北只有 2026 一年；江苏/广东/湖北/山西按院校专业组公布，表里没有专业名。所以「四年预警」目前只对辽宁是完整结论，其它省是「有多少说多少」。
5. 招生计划数只有浙江有，其余省份投档线原文不含，页面显示「—」。
6. 课程库是「平台搜索结果」不是真实课程地址。
7. **专业前景的文案是手写的判断题，不是数据推断**（`major_outlook.py` 的 `GROUP_OUTLOOK`）。它按专业类给共性判断、按关键词给细分方向修正，能覆盖 821 个专业，但「这个专业四年后一定怎样」本身无法从投档表算出来。要更强的说服力，下一步应接真实的就业/考研/考公数据（P2、P3 的活）。
