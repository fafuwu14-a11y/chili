> 依据：《赤鲤_挑战杯校级孵化项目申报书》正文与简表。
> 口径：只写能验收的事。做不到的当场降级，不写进计划。

## 一、先说结论

| 问题 | 答案 |
| --- | --- |
| 现在的系统离申报书有多远 | 代码骨架完成了约 1/3；剩下 2/3 里，一半是数据工程，一半是人工内容 |

## 四、六个阶段

### P1 申报与答辩收口（2026.11.15 – 2026.12.05，3 周）

| 项 | 内容 |
| --- | --- |
| 目标 | 让评委在 5 分钟内看懂「做了什么、和市面有什么不同」 |
| 交付 | ① 演示脚本（一条主线：测评→匹配→预测→志愿表→专业详情→前景）；② 10 页答辩 PPT；③ 五分钟录屏；④ exe 在答辩机实测通过 |
| 技术 | 无新功能，只修演示路径上暴露的问题 |
| 工时 | 学生 6 人日；AI 3 轮 |
| 验收 | 断网、干净 Windows 机器上双击 exe，全程不报错、不联网 |

> 关键：exe 目前只验证了包内容，没在真机跑过。P1 第一件事就是找一台没装 Python 的电脑实测。

### P2 就业画像一期：结构化 + 考公考研创业（2026.12.08 – 2027.02.28，12 周）

| 项 | 内容 |
| --- | --- |
| 目标 | 821 个专业从「一段话」变成「可查询、可对比、可排序的结构化画像」 |
| 数据 | `backend/data/major_profile.json`，每条约 1.5KB：学制学位、主干课程 6–10 门、核心能力 4–6 项、对口职业 5–10 个、行业 3–5 个、就业率区间、升学率区间、起薪区间、区域分布、考公类别、考研学科与评估等级、创业五维分、六维雷达分 |
| 模块 | 新增 `backend/app/major_profile.py`；路由 `/api/major/profile?name=`；`major.html` 详情改造；新建 `compare.html` 专业对比页 |
| 分步 | ① 定字段与口径（1 周）② AI 分批生成 821 条（每批 80 条，10 批）③ 抽检 10% 人工核对（2 周）④ 考公映射表（国考职位表反查）⑤ 考研学科评估表 ⑥ 前端画像卡 + 对比雷达图 |
| 工时 | AI 12–15 轮；学生 18 人日（抽检、口径、考公表核对） |
| 验收 | 随机抽 50 个专业，六段字段齐全、无空值；对比页能选 2–4 个专业出雷达图；所有数字带来源或标「区间估算」 |

> 这里最容易翻车的是「就业率」和「起薪」。计划里只写区间和来源年份，不写单点。评委问「这个 92% 哪来的」，答「某校 2024 就业质量报告，样本 300 人」——经得起问；写「就业率 92%」没有出处，一问就塌。

### P3 课程地图（2027.02.01 – 2027.04.15，10 周，与 P2 尾部并行）

| 项 | 内容 |
| --- | --- |
| 目标 | 「学这个专业看什么课」给到可点的链接和章节 |
| 数据 | `backend/data/courses.json`：168 门（56 专业类 × 3），字段含平台、院校、教师、学时、免费与否、章节列表、难度、对应知识点 |
| 模块 | 新增 `backend/app/course_map.py`；路由 `/api/course/map?major=`、`/api/course/list`；`mooc.html` 升级为课程地图 |
| 分步 | ① 抓 MOOC / 智慧教育平台课程页（只抓公开元数据，不存视频）② 人工核 168 门是否在架 ③ 建立「专业知识点 → 课程章节」映射 ④ 前端按「基础课—核心课—拓展课」三段展示 |
| 工时 | AI 8–10 轮；学生 8 人日 |
| 验收 | 任选一个专业，能给出 3 门课、每门课有直链且能打开、标注「先看第 1–3 讲」 |

> 「第几分钟」这条从计划里拿掉。要做得逐视频打标，168 门 × 40 讲 = 6720 个时间点，一个人的学期全搭进去也不够，而且平台改版就全废。

### P4 培优扶弱一期：数学一科（2027.03.01 – 2027.07.15，19 周）

| 项 | 内容 |
| --- | --- |
| 目标 | 高一数学：诊断 → 归因 → 组卷 → 错题同类推送 → 课程片段 |
| 范围 | **只做数学，只做高一**。物理作为二期候选，不进本期验收 |
| 数据 | ① 知识点树 `knowledge/math_h1.json`（约 120 个知识点，含前置关系）② 原创题 `questions/math_h1.json`（800 题，每题带知识点、难度、题型、解析）③ 知识点→课程讲次映射 |
| 模块 | 新增 `backend/app/tutor.py`；路由 `/api/tutor/diagnose`、`/api/tutor/paper`、`/api/tutor/similar`；新建 `tutor.html` |
| 分步 | ① 知识点树（2 周）② 生成 800 题 + 人工审校（6 周，最重）③ 诊断算法：按知识点正确率 + 错因标签（概念/计算/审题/速度）④ 组卷：按知识点配比抽题 ⑤ 错题本存 localStorage，服务端不落盘 ⑥ 与志愿联动：选科组合→可报专业数 |
| 工时 | AI 20–25 轮；学生 30 人日（**审题是大头**，800 题至少要过一遍） |
| 验收 | 一套 20 题诊断卷能给出「薄弱知识点 + 错因分布 + 10 题靶向练习」；错题本刷新后仍在；服务端日志无答案内容 |

> 这是全年最重的一块，也是评委最容易问「你们真做了吗」的一块。800 题必须自己审，AI 生成的题会有错解和超纲，不审就是给用户挖坑。

### P5 数据扩省：河南 + 陕西（2027.01.05 – 2027.05.30，与 P2/P3 并行）

| 项 | 内容 |
| --- | --- |

## 七、风险与建议

| 风险 | 概率 | 影响 | 应对 |
| --- | --- | --- | --- |
| 800 题审不完 | 高 | 培优模块延期 | 缩到 500 题 + 明确标注「原创题，非真题」 |
| 河南数据格式不支持专业级 | 中 | 只能做预测不能做画像 | 提前确认，专业组制就只接预测 |
| 就业率/起薪被质疑 | 中 | 答辩被问倒 | 全站只写区间 + 来源；页面加「数据口径」折叠说明 |
| 中学试用排不上 | 中 | 实证数据缺失 | 提前 2 个月联系，备选母校 |
| 论文来不及 | 中 | 产出少一项 | 改投校内学报或写成调研报告，申报书允许二选一 |
| 三人时间不够 | 高 | 全线延期 | 每期只保一个主线，P3/P4 允许砍 |

### 建议对申报书做三处口径修正（答辩时主动说）

1. **「精准到第几分钟」→「精准到第几讲」**：分钟级需要逐视频打标，平台改版即失效，性价比极低。
2. **「九科培优」→「数学先行，按学期扩展」**：九科题库是内容公司量级的工作，学生团队一年做不完，先做一科反而可信。
3. **「就业率/起薪具体数字」→「区间 + 来源年份」**：公开数据没有统一口径，写具体数字等于编，经不起追问。

这三处主动降级，比结题时被发现没做完要好。
