# 方案：门户主页 + 专业匹配深化（v2 方向调整）

> 写于 2026-10-30。对应需求：把「专业匹配」从"21 个大类排序"做成"能找到具体方向、能看四条出路、能看四年后的预警"，
> 同时补一个真正的门户主页，让功能入口一眼可见，而不是一进来就是某个功能页。

---

## 1. 现在的问题（诊断）

你说的三点，我拆成可验证的六条：

| # | 现象 | 位置 | 影响 |
| --- | --- | --- | --- |
| 1 | 没有主页，打开就是「院校录取概率预测」 | `frontend/index.html` 同时是预测页 | 用户不知道这站还能做什么，只能看到当前这一件事 |
| 2 | 功能栏是顶栏五个平铺文字 | `.topbar .nav` | 五项等权、无图标、无说明，视觉上像"标签"不像"入口" |
| 3 | 专业匹配只到 21 个大类 | `backend/app/quiz_data.py` 的 `MAJOR_PROFILES`（21 条） | 回答不了"计算机类里我该学软件工程还是网络工程" |
| 4 | 专业画像只有一句 blurb + 标签 | `MAJOR_PROFILES[...]["blurb"]` | 没有就业/考公/考研/创业四条路的差异 |
| 5 | 没有任何"未来"信息 | — | 家长最关心的"四年后这个专业还行不行"完全没有回答 |
| 6 | 专业匹配结果页止于排名 | `frontend/quiz.html` 结果区 | 用户拿到 97% 之后不知道下一步干嘛（现在只有一个"去看录取预测"按钮） |

### 2.2 主页长什么样

自上而下五段：

1. **Hero**——一句话讲清定位（"填一次分数，看清四年"），右边直接给「输分数 → 看能上哪儿」的迷你表单（复用现有预测表单的精简版，只留省/科类/分数）；
2. **四个功能卡**（不是导航链接，是带图标的卡片）：

   | 卡片 | 一句话 | 主按钮 |
   | --- | --- | --- |
   | 专业匹配 | 18/34/48 题，找到你适合的具体方向 | 开始测 |
   | 录取预测 | 9 个省份的真实投档位次，算录取概率 | 填分数 |
   | 一分一段 | 你的分数在全省排第几，三年对比 | 查位次 |
   | 志愿方案 | 按省市上限自动排冲稳保，可打印 | 生成方案 |

   每张卡下面一行小字写"什么情况下用它"，例如方案卡写"已经知道自己想去哪、只差排序时"。

3. **专业匹配深化入口**——一张横向大卡："测完能拿到什么"三栏：适合的 3 个具体专业 / 四条出路画像 / 四年后预警；
4. **可信度条**——覆盖 9 个地区 · 数据更新至 2026-07 · 2025→2026 回测中位误差 8.0 分，点进 `/about.html`；
5. **页脚**（沿用现有四栏）。

### 2.3 导航改法

顶栏从"五文字"改成"品牌 + 五项（图标 + 文字）+ 一个「更多」下拉"：

```
[赤鲤]  首页  录取预测  专业匹配  一分一段  |  志愿方案  先导课  专业详情
                                                └─ 更多 ▾
```

- 一级只留四项高频（首页/预测/匹配/一分一段），其余收进「更多」；

- 移动端：一级变横向滚动条，不折叠成汉堡菜单（页面少，藏起来更难找）。

## 3. 专业匹配深化：三个新能力

### 3.1 能力 A：大类内的方向细分

**要回答**："计算机类 97% —— 那我到底该报计算机科学与技术、软件工程，还是信息安全？"

**做法**：
1. 建一份专业目录表 `backend/app/major_catalog.py`：教育部《普通高等学校本科专业目录（2024 年）》里的 12 门类 / 93 专业类 / 845 个专业，我们只落到**21 个大类 → 每个大类 6–12 个具体专业**这一层（约 180 条），字段：
   ```python
   {"code": "080901", "name": "计算机科学与技术", "group": "计算机科学与技术",
    "degree": "工学", "years": 4, "tags": ["编程", "算法", "读研友好"]}
   ```
2. 问卷在 `standard` / `deep` 档末尾追加 **3–5 道方向题**（`d01–d05`，五级量表），按大类分支：
   - 工科："更想动手做硬件 / 更想写代码做软件 / 更想研究算法和原理 / 更想做产品和项目管理"
   - 商科："更想算账和审计 / 更想做市场和销售 / 更想研究经济和政策 / 更想管人和流程"
   - 医科、文科、理科各一套
3. 打分：`大类得分 × (0.6 + 0.4 × 方向匹配度)`，输出"适合你的 3 个具体专业"，并给出**每个专业和大类的差异点**（例如"软件工程比计算机科学与技术更偏工程落地、代码量更大、考研可选面略窄"）。

**可行性**：高。专业目录公开、稳定；难度全在人工映射质量，可以用测试卡住（每个大类至少 6 个专业、每个专业必须有 group、专业名不重复）。

**成本**：15–25 万 token（目录录入 + 21 套方向题 + 映射 + 测试）。

### 3.2 能力 B：四条出路画像（就业 / 考公 / 考研 / 创业）

**要回答**："这个专业毕业能干嘛？考公有优势吗？必须考研吗？适合自己干吗？"

**先给结论**：这四块的数据可得性差得很多，必须分级处理，**不能假装都有硬数据**。详细论证见 `FEASIBILITY-data.md`，这里是结论：

| 出路 | 数据性质 | 我们的做法 | 展示方式 |
| --- | --- | --- | --- |
| **考公** | 规则可推 | 用《公务员考试专业参考目录》做专业→岗位类别映射，算"可报岗位类别数" | 档位 + "可报 12 类岗位，其中不限专业 5 类" |
| **考研** | 半硬 | 硕士点数量（教育部学位授权点名单）+ 保研率区间 + 是否"考研大户" | 档位：必须读研 / 读研加分 / 本科够用 |
| **就业** | 软 | 麦可思公开摘要（约 50 个高频专业）+ 学科评估等级 + 行业工资中位数 | 三段式："主流去向 / 起薪区间 / 集中行业"，标来源与年份 |
| **创业** | 定性 | 规则打标签：资质门槛、资本门槛、技能可迁移性 | 一句话 + 三个标签（如"低门槛 / 重资质 / 靠人脉"） |

**统一约定**（这条比数据本身重要）：
- 每个数字后面必须跟来源与年份，例如「月收入中位数 6,800 元（麦可思 2025 报告，全国本科）」
- 拿不到硬数据就写档位，不写伪精确数字
- 结果页底部固定一行：「以上为公开资料与统计口径的整理，不是对个人的承诺」

### 3.3 能力 C：四年后预警

**要回答**："这个专业四年后还值不值？"

**这是四条里唯一能真算的**，因为数据就在我们手上：

指标（每个专业）：
1. **招生规模同比**——该专业在 9 个省近 3 年的招生计划数变化（浙江/河北/山东有 `plan` 字段，其余省份用"专业组数量"代理）；
2. **热度漂移**——该专业录取位次中位数的 3 年趋势（位次整体后移 = 变冷）；
3. **供给信号**——教育部每年公布的「新增备案专业 / 撤销专业」名单里，该专业是否在扩张名单上。

输出三档：
- 🔴 **供给扩张**：招生计划 3 年累计涨 20%+ → "四年后同届毕业生更多，竞争会更激烈"
- 🟡 **平稳**
- 🟢 **收缩**：计划下滑或大量撤销 → "招生在收缩，但也要看是不是被更强的学校集中了"

每条预警必须带：数据年份、样本省份数、原始数字。**不说"好/不好"，只说供给和热度在往哪走。**

## 6. 风险

| 风险 | 处理 |
| --- | --- |
| 就业数据来源不硬，容易被质疑 | 只写档位不写伪精确数字；每处标来源与年份；结果页固定免责行 |
| 方向细分靠人工映射，可能漏专业 | 测试卡：每类 ≥6 个专业、group 必填、名称不重复、总数 ≥150 |
| 考公映射基于专业目录，不是实时岗位 | 明确写"按《专业参考目录》推断可报类别，实际以当年职位表为准" |
| 四年预警被误读为"这专业要凉" | 只说供给与热度方向，附原始数字与年份；不给"好/坏"结论 |
| 主页改动打断老用户习惯 | `/` 带老参数自动 302 到 `/predict.html`；导航里预测仍在第二位 |

5. `python realdata/tmp_run_tests.py` 全过，新增测试覆盖：目录完整性、方向题分支、预警三档、出路档案字段齐全；
